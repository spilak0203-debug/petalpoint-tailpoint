# 디자인 결정

## 팩 이름
- B → **Petalpoint** (slug `petalpoint`), D → **Tailpoint** (slug `tailpoint`).
- 같은 "명사 + point" 모양으로 자매 팩임을 보이고, 부드러운 꽃잎(연보라 다트)과 떨어진 꼬리(라임 캡슐)로 둘을 구분한다. "Android", "Material", "Google", "Pixel"은 상표라서 쓰지 않는다. 검색에서 같은 이름의 커서 팩은 찾지 못했다.

## 작업 방식
- 커서는 Photocraft 벡터 도형으로 그린다. 원본은 `design/*.pcraft`, 미리보기는 `design/*.png`.
- 32칸 격자(1칸 = 32px 커서의 1px) 위에 설계하고, 크게 그린 모습과 실제 32·48px 모습을 어두운 배경·밝은 배경에 함께 놓고 판단한다.
- 이유: 크게 보고 다듬되, 실제 크기에서 읽히는지를 같은 화면에서 바로 확인하기 위해.

## 방향
| 안 | 상태 | 요지 |
|---|---|---|
| A 네온 유리 | 제외 | 어두운 몸체 + 청록 빛 테두리 |
| B 머티리얼 유 파스텔 | 진행 (17종) | 연보라 톤 몸체, 짙은 남보라 테두리, 둥근 모서리, 부드러운 그림자 |
| C 시그널 팁 | 제외 | B의 형태(손 구조, 링 + 호)를 색만 바꿔 따른 안이라 새 안으로 보기 어려움 |
| D 캡슐 테일 | 시안 | 흰 화살촉 + 떨어져 따라오는 라임 캡슐. 캡슐 하나가 모든 상태를 알린다 |

## B 머티리얼 유 파스텔
- 색: 테두리 `#21005D`, 진행 `#6750A4`, `#D0BCFF`, 트랙 `#EADDFF`, 몸체 `#FBF7FF`→`#EADDFF`, 그림자 `#1D1036` 32%.
- 화살표: 꼬리 없는 다트, 테두리 1.4칸. 손: 둥근 사각형을 합친 손. 사용 중: 연보라 링 위 짙은 보라 호.
- 17종 공통 규칙 (원본 `design/b-pastel.pcraft`, 그룹 `cur/<레지스트리 이름>`, 1칸 = 8px; 클릭 지점·프레임은 `design/b-pastel-spec.json`):
  - 몸체: 모든 면은 같은 그라데이션 + 1.4칸 `#21005D` 테두리(둥근 이음) + 같은 그림자.
  - 정밀 커서(텍스트·정밀도 선택): 밝은 심 1px + 바깥 어두운 테두리 1px, 픽셀 격자에 맞춤. 정밀도 선택은 가운데 2px 틈 + 3×3 점.
  - 화살촉 하나를 공유: 크기 조절 4종, 이동(작게), 대체 선택. 대각선은 세로 화살표를 ±45° 돌린 것.
  - 배지 자리: 도움말·백그라운드 작업·위치·사용자 선택은 화살표를 그대로 두고, 고정된 원(중심 24.3,24.3, 반지름 6.1, 테두리 1.2칸) 안에 표시를 넣는다. 배지 색은 `#7F67BE`(어두운·밝은 배경 모두 대비 약 4.2:1. `#6750A4`는 어두운 배경에서 2.99:1).
  - 숨쉬기(화살표·손): 몸체 색만 한 단계 진해졌다(`#F1E8FF`→`#D9C7FF`) 돌아옴. 모양·클릭 지점은 고정. 6프레임 1200/160/160/560/160/160ms = 2.4초.
  - 회전(사용 중·백그라운드 작업): 12프레임 × 100ms(6지피) = 1.2초에 한 바퀴, 호 길이가 24%↔44%로 변함. 0번 프레임은 정지 커서(34%). Windows의 .ani 시간 단위가 1/60초라 90ms는 정확히 낼 수 없어서 100ms로 맞췄다(D와 같음).
  - 호는 점선 대신 끝이 둥근 채운 도형으로 그린다. 작은 배율에서 점선이 가늘고 짧게 나오기 때문.
- 알려진 약점: 32px에서 백그라운드 작업의 작은 회전 표시가 테두리에 묻힘. 48px에서 1px 선이 흐려짐(내보낼 때 텍스트·정밀도 선택은 따로 손볼 수 있음). 대각선 화살촉이 모서리 괄호처럼 보임. 손이 화살표보다 큼.
- 내보내기 주의: 크기를 줄여서 다시 그리면 점선이 깨지므로, 원본 배율로 그린 뒤 픽셀을 줄인다.

## D 캡슐 테일
- 색: 잉크 `#0F1411`(테두리 1.4칸, 작은 요소 1.2칸), 화살촉 `#FFFFFF`, 라임 `#C4F23A`. 그림자·번짐·그라데이션 없음.
- 기본 화살표: 화살촉 + 화살 축(67.5°) 위로 2.6칸 떨어진 라임 캡슐 꼬리. 클릭 지점 (3,2).
- 링크: 손 대신 라임 화살촉 + 끝 둘레의 클릭 표시 세 개. 클릭 지점 (11,11).
  - 이유: 클릭 지점이 기본 화살표처럼 화살촉 끝이라, 링크 위로 옮겨가도 가리키는 점이 움직이지 않는다. "화살표 + 클릭 표시"는 널리 쓰이는 클릭 기호다.
- 사용 중: 흰 캡슐 안 라임 점 세 개. 클릭 지점 (16,16).
  - 진행 막대 모양은 32px에서 꺼진 토글 스위치로 읽혀서 뺐다.
- 움직임: 꼬리가 2.4초 주기로 살짝 멀어졌다 돌아옴(기본), 클릭 표시가 바깥으로 퍼짐(링크), 점이 차례로 캡슐처럼 늘어남(사용 중).
- 나머지 역할로 늘리는 규칙: 도움말 = 화살촉 + "?" 캡슐, 텍스트 = 세로 캡슐 + 짧은 가로 캡슐, 손글씨 = 화살촉 + 긴 캡슐, 사용 불가 = 원 안 -45° 캡슐, 크기 조절 = 화살촉-캡슐-화살촉, 이동 = 화살촉 넷 + 가운데 점, 대체 선택 = 위 화살촉 + 세로 캡슐, 위치·사람 선택 = 화살촉 + 핀·사람 모양 캡슐, 정밀 선택 = 짧은 캡슐 넷을 십자로.
- 알려진 약점(시안 때): 32px에서 클릭 표시가 2.4px 획이라 링크는 주로 색 변화로 구분됨. 점 세 개가 "더보기" 버튼으로 읽힐 수 있음. 라임과 흰색의 대비가 낮아 잉크 테두리가 꼭 필요함.
- 17종 공통 규칙 (원본 `design/d-capsule.pcraft`, 1칸 = 8px, 구조는 B와 같음. `design/d-capsule-spec.json`):
  - 부분은 둘뿐: 가리키는 곳 = 흰 화살촉, 상태 = 라임 캡슐. 잉크 표시(?, 핀 구멍, 움직이는 점)는 라임 면 안에만 둔다.
  - 상태는 늘 꼬리 자리에서 바뀐다: 화살촉은 (3,2)에 고정하고, 67.5° 축 위 2.6칸 틈 뒤에 꼬리·도움말·위치·사람·백그라운드 작업 표시가 온다.
  - 방향 커서는 화살촉-캡슐-화살촉(크기 조절 4종은 세로를 돌린 것). 이동 = 화살촉 넷 + 라임 점, 대체 선택 = 화살촉 + 세로 캡슐, 필기 = 흰 펜촉 + 긴 라임 캡슐.
  - 정밀 커서: 픽셀에 맞춘 속심 + 1칸 잉크 테두리. 텍스트 = 흰 1px 줄기 + 라임 가로 캡슐, 정밀도 = 라임 3px 캡슐 넷 + 흰 1px 가운데 점.
- 17종을 그리며 바꾼 것:
  - 링크: 클릭 지점 (11,11) → (12,12), 클릭 표시를 굵게(라임 폭 1.2 → 2.0px), 60° 간격. 32px에서 표시가 보이게 하려고.
  - 사용 중: 정지 상태에서 첫 점이 세로 캡슐로 늘어나 있음. "더보기(…)"로 읽히는 것을 줄이려고.
  - 사용할 수 없음: 라임 고리 + 흰 막대. 흰 고리는 밝은 화면에서 과녁처럼 보여서.
- 움직임: 기본·링크 6프레임 2.4초(72,10,10,34,10,10 지피), 백그라운드 작업·사용 중 12프레임 × 100ms = 1.2초.
- 알려진 약점: 크기 조절의 가운데 캡슐이 짧음. 48px에서 정밀 커서 1px 선이 흐려짐. 필기 펜촉이 어두운 화면에서 작음. 사람 아이콘이 세로로 길다.
